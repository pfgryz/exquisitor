Dear Reviewer,

\vspace{0.25in}

Thank you for considering our manuscript for publication and for providing constructive feedback.
Hereunder you will find our detailed replies to all Your comments.
The changes are highlighted in the output of the latexdiff file attached to this cover letter.

\paragraph{Issue 1:}
\begin{displayquote}
The current quality measure shows how closely the reduced pipeline matches the results from running BLAST on all sequences. This is useful, but it is not the same as taxonomic classification accuracy. Since the CAMI dataset has known taxonomic labels, the authors should compare the predictions with these labels at one or two taxonomic levels. If this analysis is not possible, claims such as “superior classification accuracy” should be changed to “better agreement with the full BLAST results.”
\end{displayquote}

\paragraph{Answer:}
Thank you for this suggestion; we agree and have addressed it as follows. 
We conducted an additional experiment in which we compared the obtained predictions with the known taxonomic labels from the CAMI dataset. 
We report standard quality metrics (accuracy, precision, recall, and F1 score) at the relevant taxonomic level. 
We have also softened the claims regarding superior classification accuracy.


\paragraph{Issue 2:}
\begin{displayquote}
The number of clusters determines how many representative sequences are sent to BLAST. However, the author does not clearly report the number of clusters, the number of BLAST searches, or the reduction ratio in each experiment. The authors should explain how the number of clusters would be selected for a real sample, where the true number of taxa is unknown. A small sensitivity analysis using two or three cluster settings would be sufficient. Runtime, quality, and the number of BLAST queries should be reported for each setting.
\end{displayquote}

\paragraph{Answer:}
Thank you for this comment. 
The number of clusters is a parameter of the method and should be adjusted to the sample under study. 
We have added information about the number of clusters used in the experiments; the reduction ratio was $\sqrt{N}$, where $N$ is the number of sequences. 
For a real sample, the number of clusters should be chosen based on the expected number of taxa, available computational resources, and time constraints, since it directly determines the number of BLAST searches.
We also conducted an experiment with two different cluster settings and report standard quality metrics for each. 
In each setting, the number of BLAST queries equals the number of clusters.


\paragraph{Issue 3:}
\begin{displayquote}
The model was trained and mainly tested using sequences from the same CAMI human skin microbiome sample. Although the test indices were excluded from training, the authors state that duplicate sequences were not checked. This may make the results appear better than they really are. The authors should remove exact duplicates between the training, validation, and test sets and repeat the main ANN and k-mer comparison. They should also run the full Exquisitor pipeline on the unseen sample that is already included in the manuscript, rather than reporting only clustering metrics.
\end{displayquote}

\paragraph{Answer:}
We acknowledge this concern. Due to time constraints, we were unable to remove exact duplicates between the training, validation, and test sets and repeat the main ANN and $k$-mer comparison. 
However, we ran the full Exquisitor pipeline on the unseen sample already included in the manuscript and report quality metrics against the ground-truth labels.
In this setting, the ANN still outperforms NW, but the results also indicate limited generalization.


\paragraph{Issue 4:}
\begin{displayquote}
The claims about scalability are not fully supported by the current experiments. The largest test contains only 4096 sequences, and the method builds a full pairwise dissimilarity matrix, which may become expensive for larger datasets. The authors should report the runtime and peak memory for the main steps, including embedding, distance calculation, clustering, BLAST, and postprocessing. A somewhat larger test of the steps before BLAST would also be helpful. If larger inputs cannot be tested, the statements about scalability should be made more cautious.
\end{displayquote}

\paragraph{Answer:}
Thank you for this comment; we agree. As noted in the Limitations section, constructing a full pairwise dissimilarity matrix is computationally intensive. 
A possible improvement is to replace the current algorithm with a batched version or use different grouping algorithm. 
We conducted an additional experiment, but it was run on a different server, so we do not have sufficient comparable measurements to reliably assess scalability.
Following your suggestion, we have therefore made the statements about scalability more cautious in the revised manuscript.


\paragraph{Issue 5:}
\begin{displayquote}
The description of the ANN input should be clearer. The manuscript states that the input sequence length is 150 and that one-hot encoding produces a vector of size 1 × 600. Please make sure the footnote marker is formatted correctly and explain the input dimensions in one clear sentence.
\end{displayquote}

\paragraph{Answer:}
Thank you for this comment. We have rephrased the description of the ANN input to explain more clearly how the final encoded vector is obtained.
We have also corrected the formatting of the footnote marker.


\paragraph{Issue 6:}
\begin{displayquote}
Table 3 contains an incorrect column label. The columns are shown as “AMI, NMI, NMI,” but the third metric should be FMI, based on the text below the table.
\end{displayquote}

\paragraph{Answer:}
Thank you for pointing out this error. We have corrected the column headers in Table~3: the third column was incorrectly labeled as NMI and has been changed to FMI.


\paragraph{Issue 7:}
\begin{displayquote}
More implementation details should be provided for reproducibility. Please report the BLASTn version, the release date or version of the nt database, the main BLAST parameters, and the hardware used for the timing experiments. 
\end{displayquote}

\paragraph{Answer:}
We agree with your suggestion. We have added the BLASTn version, the release date/version of the nt database, the main BLAST parameters, and the hardware used for the performance experiments.


\paragraph{Other changes:}

\paragraph{Issue 1:}
\begin{displayquote}
1. The current wording may suggest that the ANN directly performs taxonomic classification. In fact, it primarily generates sequence representations and supports clustering, whereas the final identification is obtained through BLAST. The method should therefore be consistently described as an ANN-assisted representative-sequence selection framework for accelerating BLAST-based identification. The related-work section could also briefly cover recent double-strand DNA representation learning, such as the latest work CrossDNA (https://www.nature.com/articles/s42256-026-01249-1) and HyenaDNA. (https://arxiv.org/abs/2306.15794).
\end{displayquote}

\paragraph{Answer:}

Thank you for this comment. We added citations and modified text as suggested (Introduction, lines 43--53).

Currently the second last paragraph is:

\begin{quote}
    Recent studies in genomics use machine learning, especially artificial neural networks (ANNs), to represent sequences and support classification and annotation, using large context lengths [citations].
    ANNs often outperform classical heuristics, offering faster and more accurate results.
    The use of an ANN with contrastive learning for sequence clustering remains limited in the literature.
    This works leverages ANN  and contrastive learning capabilities to accelerate metagenomic identification while maintaining traditional quality levels, significantly streamlining the classification process.
  \end{quote}
  
\paragraph{Issue 2:}
\begin{displayquote}
Please clarify how sequences of different lengths are truncated or padded, how ambiguous nucleotides are encoded, how the number of clusters kkk is selected, and how the BLAST result of a representative sequence is assigned to other cluster members. The BLAST version, database, thread count, and major parameters should also be reported, preferably in a concise parameter table.
\end{displayquote}

\paragraph{Answer:}
Thank you for this suggestion.
In the Methods section, we clarified how sequences of different lengths are aligned and how ambiguous nucleotides are encoded.
We also explain how the BLAST result of representative sequence is assigned to the remaining cluster members. 
In ``Implementation Details'', we report the BLASTn version, database version, thread count, and main parameters.
In ``Clustering Algorithm'' we added information on how the number of clusters $k$ is selected.


\paragraph{Issue 3:}
\begin{displayquote}
Since the full-BLAST output is used as the reference, the reported metric measures agreement with the full-search baseline rather than classification accuracy against biological ground truth. Statements such as “superior classification accuracy” should be replaced with “higher agreement with the full-BLAST baseline” or “higher relative identification quality.” The explanation that the ANN performs better because it captures the full sequence structure should also be presented as a possible interpretation rather than a demonstrated mechanism.
\end{displayquote}

\paragraph{Answer:}
The reviewer is right. We performed additional experiments to evaluate our pipeline's predictions against the taxonomic labels included in the dataset used, thereby providing the biological ground truth. The results are included in the new version of the manuscript in section 3 Results, lines 340 - 347, and table 4. We agree with the proposed terms; therefore, we replaced the statements 'superior classification accuracy' and similar ones (in the Abstract and in the Results).


\paragraph{Issue 4:}
\begin{displayquote}
The second occurrence of s\_pos in the loss description should be s\_neg. The third column of Table 3 should apparently be labelled FMI rather than NMI, and “R64” should be written as R\^64. Equation (5) should also clarify how organisms appearing only in the obtained results are handled.
\end{displayquote}

\paragraph{Answer:}
Thank you for pointing these out. 
We corrected the second occurrence of $s_{\mathrm{pos}}$ in the loss description to $s_{\mathrm{neg}}$.
We also fixed the third column header in Table~3 (NMI $\to$ FMI) and changed ``R64'' to $R^{64}$. 
For Equation~(5), we clarified that organisms appearing only in the obtained results are not considered in the quality calculation.


\paragraph{Issue 5:}
\begin{displayquote}
The manuscript suggests possible applications to genome assembly, cell-subtype identification, and phylogenetic-tree construction, although these tasks are not evaluated. These statements should be clearly presented as future research directions. Claims regarding general applicability and scalability should also be moderated, given that the evaluation uses one main dataset and at most 4,096 sequences.
\end{displayquote}

\paragraph{Answer:}
Thank you for this comment.
We have moderated the related claims and now present possible applications as future research directions.
We have also softened the statements regarding general applicability and scalability, given the scope of the current evaluation.


\paragraph{Issue 6:}
\begin{displayquote}
The manuscript’s precision, reproducibility, and logical consistency should be improved.
\end{displayquote}

\paragraph{Answer:}
We agree.
Throughout the revised manuscript we improved precision, reproducibility, and logical consistency: we clarified the method description and evaluation claims, added implementation and parameter details needed for reproducibility, corrected notation and table labels, and moderated statements that were not fully supported by the experiments.
